# Continuous monitoring backend implementation

The feature is opt-in through `RALLY_REALTIME_ENABLED=1`; existing monitoring remains the default until rollout. Live checks use separate compact input/output contracts and canonical report projection. Provisional ASR text is session/turn scoped, replaces cumulative hypotheses, and cannot resurrect finalized turns. Compatible prefix growth and identical finalized promotion preserve in-flight authority; corrected supporting text does not.

Checks run on the existing fixed interval (ten seconds by default). Decision eligibility expires at eight seconds; first speech must begin by ten seconds from capture; transports drain for accounting until eighteen seconds. Per-meeting outstanding checks are capped at two; monitor admission caps total at ten and the provider caps live reasoning at twice configured meeting capacity, reserving two further slots for preparation/report work. No catch-up queue exists. Host controls invalidate decision generations immediately without aborting the accounting drain. Late completions only update request history/accounting. Existing unknown-cost fail-closed policy still applies and can interrupt paid ASR.

`GET /api/meetings/:id/checks?before=<sequence>` returns owner-only pages of fifty compact records with a cursor; at most approximately 10,000 records per meeting are retained. Records include source freshness, duration, state, optional accepted decision and conservative forecast. Database cascades remove them with the meeting. No new administrator transcript/history access was added.

`meeting.check` events and `Meeting.monitor` carry the current record. The provider budget forecast counts six checks per minute until the current deadline, ASR time and configured `RALLY_REPORT_RESERVE` (default $0.25). It is a conservative byte-based reservation estimate, excludes unknown AWS infrastructure cost, and is not an actual charge or grant balance. Forecasting does not increase any budget.

Agenda patches preserve stable IDs, archive retired topics as parked, require finalized evidence for completion/retirement, validate time allocations and permit at most one active topic. Consumed parked-topic time is retained as server-managed `Plan.retiredMinutes`; `topicSpentSeconds` tracks elapsed active allocation, not measured on-topic speech. Original goals remain visible in live context and the final report input. Ordinary host edits cannot increase the duration of an already started meeting, including interrupted capture.

Extensions carry a specific proposal ID/duration/deadline. UI confirmation uses `POST /api/meetings/:id/extension` with `{proposalId,accept}`. Rendering acknowledgment uses `/extension/presented` with `{proposalId}`; proposal creation alone never marks it presented. When an extension is also voiced, the backend speaks a canonical question naming the minutes and binds the proposal to that exact utterance. Spoken confirmation requires finalized evidence after presentation, explicit duration and affirmative wording, and no detected disagreement or overlap with moderator playback. Ambiguous cases remain pending for the host. Corrections dispute consent; disputed extra minutes are withheld from live time and agenda mutations until valid host reconfirmation.

Per-utterance delivery context stays separate from participant speech. The audio implementation enforces finish-once-started, a first-audio deadline and no replacement/queued speech. Teams duplex capture has its own default-off gate and requires a real acoustic rehearsal. Browser echo shielding remains enabled.

Focused validation: twenty controller/public HTTP tests pass, covering continuous unfinalized speech, input revisions/finalization, older completion order, owner boundaries, pause/logout, deadline handling, Teams input during output, proposal presentation, conflicting consent, replay, interrupted duration edits, consumed-time preservation and disputed confirmations. Backend typecheck passes. Parent integration work owns the full suite, real provider benchmark, independent final review and deployment evidence.
