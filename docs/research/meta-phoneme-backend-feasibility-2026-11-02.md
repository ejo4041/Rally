# Meta phoneme backend feasibility — 2026-11-02

Research and isolated CPU prototype; primary sources only. Checked the Hugging Face API, immutable checkpoint configuration/vocabulary files, Meta's fairseq source and first-party Python/PyTorch/package metadata. Local observations are identified separately from publisher claims. Scope expanded during the task from documentation to the isolated [FastSpeech2 experiment](../../experiments/meta-fastspeech2/README.md). No packages were installed, no paid service was invoked, and no production service was changed by this task.

## Finding and recommendation

**Yes: both released Meta LJSpeech checkpoints accept phoneme IDs at the model boundary.** Their exact published vocabulary is stressed **ARPABET**, not arbitrary IPA or text that merely resembles phones. FastSpeech2 is the practical CPU adapter candidate: direct real inference now works on the installed Python 3.12/Torch runtime without importing legacy fairseq or running a third-party neural G2P. TTS Transformer has the same phone vocabulary, but its released configuration has an older inference-key convention and its autoregressive inference path is more involved. It has not been executed here. [FastSpeech2 config](https://huggingface.co/facebook/fastspeech2-en-ljspeech/blob/a3e3e5e2e62bb7ca7514b11aa469e9c5b01a20bf/config.yaml), [FastSpeech2 vocabulary](https://huggingface.co/facebook/fastspeech2-en-ljspeech/blob/a3e3e5e2e62bb7ca7514b11aa469e9c5b01a20bf/vocab.txt), [Transformer config](https://huggingface.co/facebook/tts_transformer-en-ljspeech/blob/67f2d2749c4145497c593192f2d9d66d9adb3160/config.yaml), [Transformer vocabulary](https://huggingface.co/facebook/tts_transformer-en-ljspeech/blob/67f2d2749c4145497c593192f2d9d66d9adb3160/vocab.txt).

**MMS English does not expose the same boundary.** Its pinned tokenizer says `phonemize:false` and its vocabulary is a small character inventory. Turning on an espeak phonemizer or feeding ARPABET/IPA into that tokenizer does not transform its learned character embeddings into phoneme embeddings. Keep MMS's text frontend separate. [MMS tokenizer config](https://huggingface.co/facebook/mms-tts-eng/blob/c71de0fe7204c83f1c10820a7d696d0b450048ba/tokenizer_config.json), [MMS vocabulary](https://huggingface.co/facebook/mms-tts-eng/blob/c71de0fe7204c83f1c10820a7d696d0b450048ba/vocab.json), [Transformers VITS tokenizer implementation](https://github.com/huggingface/transformers/blob/main/src/transformers/models/vits/tokenization_vits.py).

Engineering recommendation: use **pinned FastSpeech2 + the HiFi-GAN weights bundled in that same Meta snapshot**, with the shared deterministic CMU/explicit-phone frontend, a small offline Python worker, native 22050 Hz synthesis and polyphase conversion to mono 16000 Hz PCM16. This preserves Meta-published acoustic/vocoder weights and needs no new model training. A functioning prototype was achieved during this task, making an under-eight-hour inference spike credible. Integration, listening quality and broad pronunciation coverage remain separate gates; this is not a promise that those gates fit the same time budget.

## What phoneme inference actually means

Both `vocab.txt` files are byte-identical, with 71 entries plus fairseq's four internally inserted special symbols. They include consonants such as `HH`, `DH`, `SH`, vowels with stress such as `AH0`, `OW1`, `AY2`, and `sp`/`spn`. The first entries are `AH0`, `N`, `T`, `S`, `D`, `R`, `L`, `sp`, `IH0`, `DH`. Numeric counts alongside symbols are frequencies, not token IDs. Fairseq inserts `<s>`, `<pad>`, `</s>`, `<unk>` first, so those initial vocabulary entries begin at ID 4. Its `encode_line` appends EOS by default and silently maps missing symbols to `<unk>` if the dictionary cannot add entries. The new backend instead fails on unknown tokens and appends EOS itself. [FastSpeech2 vocabulary](https://huggingface.co/facebook/fastspeech2-en-ljspeech/blob/a3e3e5e2e62bb7ca7514b11aa469e9c5b01a20bf/vocab.txt), [Transformer vocabulary](https://huggingface.co/facebook/tts_transformer-en-ljspeech/blob/67f2d2749c4145497c593192f2d9d66d9adb3160/vocab.txt), [upstream dictionary source](https://github.com/facebookresearch/fairseq/blob/3d262bb25690e4eb2e7d3c1309b1e9c406ca4b99/fairseq/data/dictionary.py).

FastSpeech2's released `config.yaml` has **`hub.phonemizer: g2p`**. Upstream `TTSHubInterface.get_model_input` phonemizes text before dictionary encoding; `phonemize(..., phonemizer="g2p")` imports `g2p_en.G2p()`. With the default punctuation policy, commas and semicolons become `sp`; non-alphanumeric items, including word spaces, periods and question marks, are dropped. Passing an ARPABET string into this *text* helper would run it through G2P again. The correct direct-phone path bypasses this helper and supplies IDs from the trained dictionary. No retraining is needed for that boundary. [Pinned FastSpeech2 config](https://huggingface.co/facebook/fastspeech2-en-ljspeech/blob/a3e3e5e2e62bb7ca7514b11aa469e9c5b01a20bf/config.yaml), [upstream hub interface](https://github.com/facebookresearch/fairseq/blob/3d262bb25690e4eb2e7d3c1309b1e9c406ca4b99/fairseq/models/text_to_speech/hub_interface.py).

Transformer's released YAML instead ends with **`inference.tokenization: g2p`**, with no `hub` section. The inspected upstream `S2TDataConfig.hub` reads only `config.get("hub", {})`, and the current hub helper consults only `task.data_cfg.hub`. Thus that helper/config combination does **not** automatically select the old `inference.tokenization` setting. This is an exact configuration mismatch, not proof that Transformer cannot consume phones. Its encoder embeds dictionary IDs, so direct encoding bypasses the stale frontend setting. Its published model-card snippet also passes one `model` to `build_generator`, whereas inspected task source expects a list and accesses `models[0]`. Do not treat the old snippets as current-runtime smoke tests. [Pinned Transformer config](https://huggingface.co/facebook/tts_transformer-en-ljspeech/blob/67f2d2749c4145497c593192f2d9d66d9adb3160/config.yaml), [data config source](https://github.com/facebookresearch/fairseq/blob/3d262bb25690e4eb2e7d3c1309b1e9c406ca4b99/fairseq/data/audio/data_cfg.py), [TTS task source](https://github.com/facebookresearch/fairseq/blob/3d262bb25690e4eb2e7d3c1309b1e9c406ca4b99/fairseq/tasks/text_to_speech.py), [Transformer encoder](https://github.com/facebookresearch/fairseq/blob/3d262bb25690e4eb2e7d3c1309b1e9c406ca4b99/fairseq/models/text_to_speech/tts_transformer.py).

Both acoustic configurations specify 80 log-Mel features, sample rate 22050, FFT/window 1024, hop length 256, global CMVN statistics and bundled HiFi-GAN. The vocoder configuration specifies upsampling `[8,8,2,2]` (product 256), 80 input mel channels and 22050 Hz output. Upstream's speech generator denormalizes acoustic output with CMVN mean/std **before** passing it to the vocoder. Skipping this step can create a numerically valid but incorrect waveform. [FastSpeech2 feature config](https://huggingface.co/facebook/fastspeech2-en-ljspeech/blob/a3e3e5e2e62bb7ca7514b11aa469e9c5b01a20bf/config.yaml), [bundled HiFi-GAN config](https://huggingface.co/facebook/fastspeech2-en-ljspeech/blob/a3e3e5e2e62bb7ca7514b11aa469e9c5b01a20bf/hifigan.json), [upstream speech generator](https://github.com/facebookresearch/fairseq/blob/3d262bb25690e4eb2e7d3c1309b1e9c406ca4b99/fairseq/speech_generator.py).

The original fairseq LJSpeech example explicitly demonstrates phoneme inputs and publishes separate Transformer/FastSpeech2 results. That corroborates the checkpoint vocabulary interpretation; the actual artifact vocabulary is the decisive inventory for this adapter. [Meta LJSpeech example](https://github.com/facebookresearch/fairseq/blob/3d262bb25690e4eb2e7d3c1309b1e9c406ca4b99/examples/speech_synthesis/docs/ljspeech_example.md).

## MMS English: the `phonemize:false` boundary

Pinned MMS English has `phonemize:false`, `normalize:true`, `is_uroman:false`, `add_blank:true`, `language:"eng"`, and `pad_token:"k"`. Its vocabulary contains lower-case Latin characters plus space, apostrophe, hyphen/en dash, underscore and a limited set of digits. It has neither ARPABET phone entries nor a general IPA inventory. [Pinned tokenizer config](https://huggingface.co/facebook/mms-tts-eng/blob/c71de0fe7204c83f1c10820a7d696d0b450048ba/tokenizer_config.json), [pinned vocabulary](https://huggingface.co/facebook/mms-tts-eng/blob/c71de0fe7204c83f1c10820a7d696d0b450048ba/vocab.json).

The tokenizer source lowercases/normalizes when configured, optionally invokes espeak when `phonemize` is true, otherwise filters normalized input against the vocabulary, then tokenizes **characters**, interspersing blank ID 0. Consequently `HH AH0 L OW1` becomes character tokens after normalization, not four phone tokens. Unsupported IPA can be filtered away. `phonemize:false` disables preprocessing; it is not an option to provide precomputed phonemes to a phoneme-trained checkpoint. The absence of trained phoneme symbols/embeddings is the substantive boundary. Retokenizing/reindexing would change the learned input interface and requires evidence beyond a flag change. [Transformers VITS tokenizer source](https://github.com/huggingface/transformers/blob/main/src/transformers/models/vits/tokenization_vits.py).

This source behavior was also inspected in the locally installed Transformers 5.21.0 file at `/srv/hackathon/tools/mms-venv/lib/python3.12/site-packages/transformers/models/vits/tokenization_vits.py`. No MMS environment settings or packages were changed. Dictionary respellings supplied as ordinary MMS text may be a separate experiment, but they do not establish true phone-level control.

## Compatibility: installed runtime versus legacy fairseq

Local read-only inspection found Python **3.12.3**, Torch **2.15.0+cpu**, Transformers **5.21.0**, NumPy **2.5.4**, SciPy **1.18.1**, PyYAML **6.0.3** in `/srv/hackathon/tools/mms-venv`. `fairseq`, `hydra-core`, `omegaconf` and `torchaudio` were absent. System `python3` exists; unqualified `python` was not on PATH. The host exposes four x86-64 virtual CPUs (AMD EPYC 9555P identity, AVX2 available), about 7.8 GiB RAM and no swap. About 4.5 GiB RAM was available at the inspection snapshot. These are shared-host observations, not reserved benchmark resources.

The PyPI fairseq 0.12.2 release supplies CPython 3.6/3.7/3.8 wheels and an sdist, with no CPython 3.12 wheel. Its metadata/setup constrain Hydra to `>=1.0.7,<1.1` and OmegaConf `<2.1`, require torchaudio, and do not cap Torch to a known compatible version. A resolver accepting a new Torch therefore does not establish runtime compatibility. [First-party release metadata](https://pypi.org/pypi/fairseq/0.12.2/json), [fairseq 0.12.2 setup](https://github.com/facebookresearch/fairseq/blob/v0.12.2/setup.py).

There is a concrete Python import issue before model inference: fairseq 0.12.2's `FairseqConfig` declares nested dataclass objects as field defaults, e.g. `common: CommonConfig = CommonConfig()`. Python 3.11+ rejects unhashable defaults such as ordinary mutable dataclass instances. This makes unmodified older fairseq a poor Python 3.12 dependency candidate, even before extension compilation and its Hydra dependencies. This conclusion follows from the source plus the Python rule; no fairseq install/import trial was performed. [Fairseq config declarations](https://github.com/facebookresearch/fairseq/blob/v0.12.2/fairseq/dataclass/configs.py), [Python dataclass mutable-default rule](https://docs.python.org/3.12/library/dataclasses.html#mutable-default-values).

Modern Torch's default checkpoint-loading policy is also relevant: from Torch 2.6, `torch.load` uses `weights_only=True` by default when no pickle module is passed. Older training checkpoints can include non-tensor objects and need an explicit loading policy/allowlist. For this exact FastSpeech2 release, pickle inspection found `argparse.Namespace`, `collections.OrderedDict`, and Torch storage/tensor rebuild globals, **not OmegaConf classes**. An allowlist for `argparse.Namespace` was sufficient for restricted CPU loading. We did not use unrestricted pickle loading. [Torch serialization policy](https://docs.pytorch.org/docs/stable/notes/serialization.html#torch-load-with-weights-only-true), [local implementation](../../experiments/meta-fastspeech2/backend.py).

An older isolated Python 3.8–3.10 environment with contemporaneous Torch/fairseq dependencies is a possible fallback, but that matrix is **unproven here** and was neither installed nor needed. Do not downgrade the MMS environment. The successful candidate instead executes selected pinned upstream class/function definitions and supplies minimal compatibility bindings, avoiding fairseq's package import graph. Upstream source is pinned to `3d262bb25690e4eb2e7d3c1309b1e9c406ca4b99`; copied files/hashes are recorded in the [vendor manifest](../../experiments/meta-fastspeech2/vendor/manifest.json).

## Prototype behavior and measured evidence

The isolated implementation is [backend.py](../../experiments/meta-fastspeech2/backend.py) plus [worker.py](../../experiments/meta-fastspeech2/worker.py). It preserves upstream FastSpeech2 FFT blocks, attention, variance predictors, sinusoidal positions, length regulator and HiFi-GAN generator. It verifies the six artifacts, reads the original model configuration, constructs the original 75-row token embedding and loads state dictionaries strictly. It handles the deprecated positional `_float_tensor` key through upstream's positional module loader. CMVN is inverted, the bundled vocoder generates native audio, and SciPy resamples by 320/441 to 16000 Hz. This is a small compatibility loader, not an independent reimplementation or a third-party TTS checkpoint. [Upstream FastSpeech2](https://github.com/facebookresearch/fairseq/blob/3d262bb25690e4eb2e7d3c1309b1e9c406ca4b99/fairseq/models/text_to_speech/fastspeech2.py), [upstream HiFi-GAN](https://github.com/facebookresearch/fairseq/blob/3d262bb25690e4eb2e7d3c1309b1e9c406ca4b99/fairseq/models/text_to_speech/hifigan.py), [SciPy resample_poly](https://docs.scipy.org/doc/scipy/reference/generated/scipy.signal.resample_poly.html).

One observed runtime failure was fixed by explicitly importing `torch.onnx.operators`: upstream sinusoidal positional embeddings call `torch.onnx.operators.shape_as_tensor`, but importing `torch` alone does not populate that submodule in this runtime. Legacy weight-normalization emits a deprecation warning on stderr; loading and inference succeed. [Upstream positional embeddings](https://github.com/facebookresearch/fairseq/blob/3d262bb25690e4eb2e7d3c1309b1e9c406ca4b99/fairseq/modules/sinusoidal_positional_embedding.py).

The coordinating main agent independently reported its first actual JS-wrapper test passed: 35 phones for “Meta follows the agenda and reviews the evidence”, output 2.763 s, warm request 1.203 s, model-reported initialization 748 ms and roughly 2 s process startup. That report is attributed session evidence, not a second measurement made by this task. Shared-corpus measurements belong to main-owned `scripts/phoneme-benchmark.mjs`; do not infer corpus results from either probe.

No separate holdout corpus is retained here. The authoritative frozen 20-development/20-validation corpus is [scripts/fixtures/phoneme-corpus.json](../../scripts/fixtures/phoneme-corpus.json). An initially separate dictionary-derived smoke set was removed before use as evaluation evidence, because it overlapped development content and selected a contextual dictionary variant without semantic resolution. It must not be called an independent holdout. The backend remained at upstream factor 1.0 while the main agent ran the frozen corpus; duration changes require a separately labeled candidate. The initial corpus run preceded the final sentence-join interface and is preliminary evidence only. The final worker supports optional `sentences:[{text?,phones,pauseMs}]`, 1–32 segments: total phones must remain at most 300 and concatenate exactly to top-level `phones`; pauses are integer 0 or 300 ms. All segments are validated before inference. Each segment is synthesized independently with backend EOS; mono PCM is concatenated with explicit zero-filled silence, limited to 30 seconds overall. Multi-segment joins use 5 ms fades; a one-segment/zero-pause request preserves PCM bytes. Responses include phrase start/end seconds and pause lengths. These worker changes do not alter model controls. The final benchmark must use this frozen interface rather than relabeling earlier measurements.

### Worker integration boundary

The CLI accepts `--model-directory`, optional identity arguments `--model-id`/`--model-revision` restricted to the pins above, and a one-shot `--phones-json` probe with optional `--output`. The persistent worker emits ready identity with `sampleRate:16000,inputKind:"arpabet"`; consumes JSONL `{id,text,phones,prosody?}`; and returns the MMS-shaped audio envelope `{type:"audio",id,model,revision,sampleRate:16000,seconds,synthesisMs,pcmBase64}`. Text is metadata; phones drive synthesis. See the [experiment README](../../experiments/meta-fastspeech2/README.md) for reproducible commands and exact optional timing fields.

The worker requires 1–80-character string IDs without ASCII controls/DEL, checks optional text/input kind, bounds/drains request lines, rejects unknown/special/EOS phones, rejects empty or over-300-phone input, and appends EOS exactly once. Unsupported prosody fails explicitly; absent/null/empty-object prosody uses factors 1.0. Predicted expansion is capped at 2500 frames before length regulation, about 29 seconds at the native rate. Full waveform generation precedes the response; cancellation is by wrapper-owned process termination, not streaming/in-process interruption. The experiment has no production route or deployment changes of its own. The coordinating agent owns adapter/API/Teams integration; none of those files were edited by this backend task.

Focused [integrity/protocol tests](../../experiments/meta-fastspeech2/test_backend.py) cover hash corruption before deserialization, special/unknown token rejection, EOS insertion, phone/prosody limits, valid PCM duration, ID/control/input-kind constraints and oversized-line recovery. An initial test-run issue involved setting Torch's process-global interop thread count twice during a second test-only constructor; the integrity test isolates that unrelated setting. **Final focused check: 9 tests passed in 1.277 seconds** on the installed runtime after the initial corpus process completed. Log: `artifacts/feedback/phoneme-prototype/tests.log` (ignored). Additional checks cover sentence-join validation before any inference, exact pause-byte count, unchanged single-sentence PCM and joined-output duration limits.
