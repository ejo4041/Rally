The host can select a meeting browser tab and optionally include their microphone. WhatsApp Web is the first preset; Zoom Web, Google Meet, Jitsi and Other use the same audio interface. The browser picker requires a tab with shared audio. Only audio enters the existing Muse transcription pipeline; screen frames are neither sent nor saved. Moderation is shown to the host, with local voice optional. This route does not join the call as a participant or inject speech into it.

Completed meetings can generate a preview containing only explicitly confirmed outcomes with current, non-echo transcript evidence. The host can copy it or open a WhatsApp draft, choose a recipient and send manually. No messaging API or additional connector subscription is used. Existing Muse processing remains subject to its normal charges and budget gates.

Validation: 44 application tests and four local browser scenarios passed. The new browser scenario mixed synthetic 440 Hz remote and 880 Hz microphone audio through the real AudioContext and 16 kHz PCM worklet, verified both signals, rejected missing audio/screen selection before opening a model session, and verified Stop sharing closes every track. WhatsApp draft preview/URL tests opened no external message. [Synthetic measurements](../research/platform-browser-check.json).

The protected deployed check verified the new module, display-capture permission policy, persisted platform settings, confirmed-only follow-up and unchanged Muse usage.
